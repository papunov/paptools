# PersonalManager Finance Core

## 1. Транзакции и Категории (`Transaction.cs`, `Category.cs`)

Транзакциите са основните финансови записи в системата:

```csharp
public class Transaction
{
    public ObjectId Id { get; set; }
    public ObjectId UserId { get; set; }
    public ObjectId SalaryId { get; set; } = ObjectId.Empty;
    public ObjectId CategoryId { get; set; }
    public string CategoryName { get; set; }
    public decimal Sum { get; set; }
    public string Comment { get; set; }
    public bool Expense { get; set; } // true = Разход, false = Приход
    public bool Marked { get; set; }  // Маркирана за специален отчет
    public DateTime AddedOn { get; set; }
}
```

### Важни правила при транзакции:
- Полето `Expense` определя дали сумата е приход (`false`) или разход (`true`).
- Полето `SalaryId` свързва транзакцията с конкретен месечен бюджет/заплата (`Salary`).

---

## 2. Заплати и Месечни Бюджети (`Salary.cs`, `SumSalary.cs`)

Системата групира разходите по месечни периоди (заплати):
- **`Salary`**: Представлява период на заплата с начална дата, крайна дата и очакван приход.
- **`SumSalary`**: Изчислява общия сумарен баланс, спестявания и балансови съотношения за даден период.

---

## 3. Планирани и Периодични Разходи

- **`PlannedExpense`**: Планиран еднократен разход за даден месец с приоритет и статут на изпълнение.
- **`RecurringExpense`**: Автоматично повтарящ се разход (напр. наем, абонамент), който се генерира от `DailyCronJob`.

---

## 4. Сканиране и Мапинг на Касови Бележки (`Receipt.cs`, `ReceiptMap.cs`, `ReceiptExpression.cs`)

Системата поддържа мапинг на касови бележки чрез регулярни изрази (`Regex`):
- `Receipt`: Документ за сканирана бележка (QR код или текст).
- `ReceiptMap`: Мапинг между текст от бележка и категория в системата.
- `ReceiptExpression`: Шаблон (Regex) за парсване на специфични вериги магазини.

---

## 5. UI Компоненти и Финансови Модули (`Web.ManagerV2`)

1. **`AddNewTransaction.razor` & `.cs`**:
   - Форма за въвеждане на приходи и разходи, избиране на категория, въвеждане на бележки и тагове.
   - Стилизирана с CSS токени за пълна съвместимост с Dark Theme (`var(--card-bg)`, `var(--text-primary)`).
2. **`RecurringExpenseConfiguration.razor` & `.cs`**:
   - Конфигуриране на регулярни повтарящи се плащания (наеми, сметки, абонаменти).
   - **Защита на данните**: Изтриването на рекурентен разход изисква потвърждение с `DialogService.Confirm`.
   - **Управление на зареждането**: Използва булев флаг `isLoading` и локализиран `EmptyText="Няма конфигурирани регулярни разходи"`.
3. **`Export.razor` & `.cs`**:
   - Експорт на финансови транзакции, заплати и баланси в Excel / CSV формат.
   - Таблицата за избор на периоди и данни ползва булев индикатор `isLoading`, баджове със съобразени цветове за тъмна тема и `EmptyText="Няма намерени записи за експорт"`.
4. **`Balance.razor` & `.cs`**:
   - Основен месечен баланс: визуализация на разходи по категории, спестявания, планирани разходи и изпълнение на бюджета.
5. **`AddQR.razor`**:
   - Модул за ръчно качване и сканиране на QR кодове от фискални бонове и интеграция с GCP Document OCR.
6. **`Subscriptions.razor`**:
   - Оптимизатор на абонаменти и повтарящи се разходи (`/subscriptions`): хронологичен календар на плащанията за месеца, интелигентно откриване на абонаменти от историята на транзакциите, разбивка по категории и симулатор на спестявания при инвестиране със сложна лихва.

---

## 6. UI, UX и Защита на Данните във Финансовия Модул

- **CSS Токени**: Използване единствено на семантични CSS токени (`var(--card-bg)`, `var(--text-primary)`, `var(--bg-primary)`, `var(--border-color)`). Строго са забранени класове като `bg-white`, `bg-light` или `text-dark`.
- **Защита срещу безкрайно въртене на спинъра**: Забранено е обвързването на индикатора за зареждане с броя елементи (`IsLoading="Model.Count == 0"`). Използва се булев флаг `isLoading = true` преди извикване на сервиза и `isLoading = false` в `finally`.
- **Локализирани празни състояния**: Всеки грид (`RadzenDataGrid`) задължително дефинира атрибута `EmptyText` (напр. `"Няма намерени транзакции"`).
- **Потвърждение при изтриване**: Всички бутони за изтриване на финансови записи, категории или конфигурации извикват `DialogService.Confirm` с бутони за отказ и потвърждение.
